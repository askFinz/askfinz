## Key points

### Ask why a direction was dropped

Cancelled and deprioritised issues are the cheapest institutional memory a team has, and nobody browses them. Connected, they answer questions — so the argument that was already had does not get had again.

### Check a proposal against what was already agreed

Before you write the brief, ask whether the team has already settled the question. The answer names the issue or project update it came from, so you can quote it rather than paraphrase it.

### Onboard without borrowing someone's afternoon

A new engineer can ask why a feature works the way it does in Chat and get the reasoning from the issues that preceded the build, instead of reconstructing it from someone's memory.
